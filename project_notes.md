## As built
_Kept up to date by Claude._
### Overview
Interactive web pages, with no build step, that show what the boxes in a deep-learning architecture diagram actually compute. Five pages exist. Three are for the same toy CNN: a 2D page (convolution one output cell at a time, ReLU, pooling, channels, receptive field, through to a prediction), a 3D page (the same network drawn as H×W×C blocks with three.js, with kernel sweeps and receptive-field cones), and a training page (real MNIST digits shrunk to 16×16 stream in; one SGD step is shown in full, forward, loss, backward, update, then the arc of many with curves, kernels over time and accuracy on held-out digits; weights trained there load into the other two pages). The fourth is the Vision Transformer explorer, on the same digits and on weights trained offline: patches → tokens → position → one encoder block with two attention heads → average → 10 classes, with a pinned overview line and five sections that zoom into it. The fifth is the ViT training page (`vit-train/`): one training step in full, with the backward pass through attention a stage at a time, then many steps live, then a measured comparison and a live race against the CNN on 100 to 3,000 digits; its weights load into the ViT explorer. The repo's CLAUDE.md says: "Purpose: interactive, visual explanations of how DL architectures compute (CNN and ViT built, each with an explorer and a training page; then U-Net, CoAtNet, ConvNeXt, in that order)." Alexy, 2026-10-12: the project is to "visualise different models, starting with DL", ported locally "to add to it without being limited by artifacts size, versioning and such."

### Method
- Plain HTML plus ES modules, served statically. GitHub Pages deploys the repo root from `main` (`.github/workflows/pages.yml`). Local run: `python -m http.server 8000` from the repo root (modules need http, not file://); tests: `node core/cnn.test.mjs`, `node core/data.test.mjs`, `node core/train.test.mjs`, `node core/vit.test.mjs`, `node core/race.test.mjs`.
- Toy network: 16×16×1 input → conv1 (4 hand-picked 3×3 kernels: Sobel-x, Sobel-y, Laplacian, diagonal; stride, padding and dilation selectable) + ReLU → 2×2 pool (max or average, a toggle on both pages) → conv2 (8 random 3×3×4 kernels) + ReLU → 2×2 pool → global average (8 values) → FC 8×10 (random) → softmax over 10 classes. The 2D page can also switch the activation off. On the CNN explorer pages' default weights nothing is trained; they say so wherever a prediction appears.
- `core/cnn.js` holds the forward pass, pooling, softmax, receptive-field propagation and the kernel and input presets, as pure functions with a test. Both pages are ES modules (`<script type="module">`) that import it; each keeps only display code plus two thin wrappers: the 2D page builds the zero-padded input it draws in stage 2, and both pages resolve the head probes (a global-average entry, a class, a score, an input pixel) before calling the core `footprint`. `forward` takes `activation: 'relu' | 'none'` (the 2D ReLU toggle) and `poolMode: 'max' | 'avg'`; `footprint` takes one cell `{stage, r, c, ch}` or a region `{stage, rect, ch | chs}`.
- Interaction grammar shared by every page: yellow = forward kernel window, green = receptive field traced backward; hovering any cell highlights its receptive field in every upstream tensor; technical terms get a dotted inline definition plus a Terms section on both pages. The 3D readout for a pooled cube writes out the 2×2 block it summarises, as the 2D page does. At the head, both pages show only the direct link: a global-average entry lights its pool-2 map, an FC weight lights its average and its class, a class lights the 8 averages and its column of W; the cone back to the input is not drawn there.
- `ui/terms.js` and `ui/terms.css` hold the terms mechanism (the `TERMS` array, the dotted definitions with their tooltip, the Terms section); both pages import `installTerms` with their own text selectors. Terms are linked at their first mention per paragraph, in order of appearance; dynamic text (readouts, the sweep hint) is left unlinked.
- 3D depth layout: the default "whole network" camera looks from high up and nearly head-on from the input end, so the stages recede as a staircase and the input hides nothing; chosen from headless-Edge screenshots of nine candidate presets at two window widths.
- `core/train.js` holds the training maths as pure functions: `gradFootprint`, the backward mirror of the receptive field (which later gradient cells a gradient value is a sum over, up to the scores); cross-entropy loss; the backward pass (scores p − y → FC → global average, a 16th to each cell → pool routing, max to the first maximum or average spread → ReLU gate → conv kernel and input gradients at stride 1, pad 1); He-uniform initialisation (±√(6/fan_in), seeded, or the hand-picked bank for layer 1); one SGD step; batch averaging; prediction; accuracy; a seeded shuffled order. `core/data.js` reads `data/mnist16.bin`: 3,000 training and 1,000 test MNIST digits, 300 and 100 per class, area-resampled from 28×28 to 16×16 by `tools/make_mnist16.py` (standard-library Python, seed 1; format and CC BY-SA 3.0 attribution in `data/README.md`).
- Training page `cnn-train/`. Band 1, One step: a phase strip digit → forward → back: FC → back: layer 2 → back: layer 1 → update; Step runs one phase, Next digit finishes the digit and brings the next. The gradient is computed in one go when the backward pass starts and revealed a layer at a time from the loss towards the input; each backward step frames in green what it computed and lights its arrows, and cells not computed yet are drawn faint in place so nothing moves between phases. In 2D the whole network is one line in a horizontally scrolling frame (fits a window of about 1600 px), laid out as the data flows with each layer's weights between the map they read and the map they make (layer-1 kernels between digit and conv 1, layer-2 kernels between pool 1 and conv 2, FC weights and biases between the averages and the softmax), weight columns tinted; three rows: forward (activations and w), backward (the gradient of each, under it), update (w′ = w − lr·∂L/∂w under each weight); channel k is one horizontal line through its kernel, its maps, its average and its row of FC weights. Hover, in green, shows what a value is computed from: an activation's receptive field upstream and the kernel that made its map; a gradient's sources downstream up to the loss and the weights the error came through; a weight in all three rows with the two maps whose product is its gradient. Band 2, Many steps: Play and Restart (new seed, everything cleared), play at 2, 10, 50 or 200 digits a second (default 200), learning rate 0.001 to 0.5 (default 0.1), batch 1, 8 or 32, Restart from edge detectors; loss per digit and its running average; training accuracy over the last 200 digits and held-out accuracy on the 1,000 test digits every 200; layer-1 kernels at 0, 100, 300, 1,000, 3,000 and 10,000 digits; the last 20 digits with their guesses. The maths runs at full speed in a frame loop; the play band redraws ten times a second. While playing, the step band follows: each frame stops with the digit on show at the end of its backward pass, and the band redraws when a new digit is on show, at most ten times a second (about one digit in 20 at 200 a second, every digit at 2). A hovered cell or weight stays probed, so its readout and highlight follow from digit to digit. Pressing Play takes the current digit to the end of its backward pass; Pause leaves it there for Step to update. Design: `docs/superpowers/specs/2026-10-14-cnn-training-layout-design.md`.
- The training page's One-step band has a 2D | 3D switch (remembered in local storage). In 3D one WebGL view shows the same three rows: forward (digit, layer-1 kernels as 3×3×4 with kernels into depth like conv 1's channels, conv 1, pool 1, the eight layer-2 kernels in a 2 × 4 grid with slices into depth like pool 1's channels, conv 2, pool 2, average, FC weights with the biases beneath, softmax), the gradients beneath, and w′ beneath the weights; weight groups framed in the accent colour in every row, and the blocks the last backward step computed framed in green. The same readouts answer a hovered cube, and the highlights are boxes and connectors following the same rules as 2D. A "side by side | depth" switch (remembered) sets the layout; in depth each row runs away from the viewer and the rows become lanes 30 apart, the scores stand beside the FC weights, stages 14 apart with 18 after the averages, and labels that would overlap a nearer one are hidden. Camera presets whole · forward · backward · update frame a complete step's layout by projecting every block's corners, with room for the labels (theta/phi/padding side 0.3/1.2/1.03, 0.35/1.15/1.04, 0.35/1.2/1.03, 0.3/1.2/1.04; depth 0.35/1.05/1.04, 0.55/0.9/1.06, 0.4/1.0/1.05, 0.3/1.0/1.05). Block data are read at draw time, so a new digit is a refresh of colours and sizes, not a rebuild.
- `ui/blocks3d.js` holds the 3D block renderer (scene, instanced cubes, highlight boxes, connectors, labels, orbit camera, picking, render loop) shared by the 3D explorer and the training page; a page declares blocks with rows and positions and keeps its own presets, probes and readouts. Rows stack downwards side by side and become lanes in depth; a block can take another's place along the flow (`at`), set its own depth gap (`gapZ`), shift within its row (`dx`, `dy`), or hold its place without being drawn (`ghost`); `place(defs)` lays blocks out without building them, for camera fits; `declutter` hides labels that would overlap nearer ones; rebuilt meshes are disposed.
- Hand-off: "Use these weights" stores them in local storage (`ui/trained.js`, key `dl-explorer.weights.v1`, with digits seen, passes, held-out accuracy, learning rate, date); the 2D and 3D pages load them at start, show a banner with a "back to the hand-picked kernels" link, and change their "weights are random" wording. "Download JSON" saves the same object.
- Landing page `index.html` ("Visualising AI"): a short lede, chips linking to each architecture with its status, a key to the colour grammar (yellow forward window, green backward trace, blue-to-orange values, dotted terms), then one section per architecture in Alexy's order: CNN (3 pages, as cards), Vision Transformer (2 pages: Explorer and Training cards), U-Net, CoAtNet, ConvNeXt (planned). Each section has a schematic of the architecture's shape drawn in SVG by a small script (blocks whose depth is channels, in the pages' colours, light and dark; the ViT's shows tokens, an encoder with one token's attention in green, an average and 10 classes), a one-line definition, the question it asks against its neighbours, and for planned ones what the page will show and what it builds on. Its few terms are explained in the text rather than as dotted tooltips, because the shared glossary would otherwise list every architecture's terms on every page. The three CNN pages and the two ViT pages carry a breadcrumb back to it. Footer: source link and the MNIST attribution.
- `ui/grid.js` holds the canvas grid drawing and hit-testing (`drawGrid`, `cellAt`, colours, `fmt`, which never prints "-0") shared by the 2D and training pages.
- Vision Transformer explorer `vit/index.html`. Model, as in the spec: 16×16 digit → sixteen 4×4 patches (a strided convolution) → 16 tokens of 8 numbers, plus a learned position table → one encoder block (LayerNorm, two attention heads of 4 numbers, join → Wo, residual, LayerNorm, MLP 8 → 32 → 8, residual) → the 16 tokens averaged (no class token) → 10 classes; 1,242 weights. `core/vit.js` holds the forward pass, the backward pass, SGD and Adam updates, `tensor`/`SHAPES` (the named tensors every view reads) and `vitTrace(S, { t, r, c })`, the rules that say which values a hovered one reads. `tools/train_vit.mjs` trains it (SGD or Adam, picked by the 3-point rule below) and writes `models/vit16.json`. The page: a pinned overview line, token i on row i, plus five sections made by one column builder (a section is the overview's columns at a larger cell size, and every copy of a tensor lights together on hover); attention is laid out as a matrix product, with Kᵀ and Vᵀ as columns above the map; a yellow patch sweep and an attention walk; a shuffle demo (with position off, shuffling the patches leaves the output unchanged); a trained | random switch and a fallback banner when the weights file is missing (the trained button is then disabled); the page says which weights it runs on, with the held-out accuracy, wherever a prediction appears, and states the setting that accuracy was measured in (position on, patches in reading order); with position off it shows the position-off figure (`meta.testAccNoPos`), with patches shuffled it says the figure is for reading order. After attention green is graded by the attention weight, its alpha proportional to the strength. Terms come from `VIT_TERMS` in `ui/terms.js`.
- `ui/grid.js` gained for the ViT page: `drawGrid` options `glow` (graded green), `win` (yellow window), `blocks` and `lines`.
- ViT training page `vit-train/index.html`, three bands. Band 1, One step: the explorer's forward line drawn with the LayerNorm outputs h₁ and h₂ as columns (they are what Wq, Wk, Wv and W₁ read), three rows (forward, backward, update), a phase strip that reveals the stages one at a time (`BACK_STAGES` in `core/vit.js`: faint views 94 → 74 → 64 → 51 → 24 → 0 across the phases; green-framed views 0, 0, 10, 13, 27, 24, 0), the page's 122 views drawn by `ui/vitline.js`. Green runs downstream from a gradient and, through attention, is graded by a column of the map (the queries that read a token), the mirror of the forward row; a weight readout writes out `w`, `∂L/∂w` and `w′ = w − lr·∂L/∂w`, showing a gradient only for the digit on show. Band 2, Many steps: Play and Restart, plain SGD (the explorer's update rule) with a learning-rate slider, batch 1, 8 or 32 (changing it at the update phase is safe), loss and held-out accuracy curves, snapshots of attention and of the position table at fixed digit counts, the last 20 digits with their guesses; the maths runs in a frame loop and 300 digits of play give weights identical to a plain `core/vit.js` loop. Hand-off: "Use these weights" stores them (`ui/trained.js`, key `dl-explorer.vit-weights.v1`); `loadTrainedViT` also requires finite `meta.digits`, `testAcc` and `lr`, so a malformed hand-off is ignored; `vit/` loads it with a banner and a link to `vit-train/`. Band 3, ViT against CNN: a chart drawn from `models/vit_vs_cnn.json` (5 seeds per size, 100 to 3,000 digits, 30,000 steps) with its notes computed from that file (with the file missing the page says so), and a live race that trains both models on the same digits and evaluates every 2,000 steps (about 0.6 s for both models on 1,000 held-out digits); a finished race lands on the chart as hollow dots. With the digits missing every control is disabled. 2D only. Terms from `VIT_TRAIN_TERMS` in `ui/terms.js`. Design: the 2026-10-28 ViT training page spec and plan (Map).
- `core/race.js` (`RACE`, `racer`) steps the CNN and the ViT on the same balanced digit subsets, one training step at a time with a shared evaluation; its test `core/race.test.mjs` checks balanced subsets, that the racer equals a plain loop, and the ViT racer. `tools/vit_vs_cnn.mjs` runs the offline comparison (40 trainings) and writes `models/vit_vs_cnn.json`. `ui/vitline.js` and `ui/vitline.css` hold the ViT pages' tensor drawing (views, lines of one or several rows, arcs, paint), moved out of `vit/` and shared with `vit-train/`.
- `core/vit.js` gained `back` (the activation gradients, keyed like `ACTIVATIONS` without `digit`), `nudge` (one SGD step on a given gradient), `gradTrace` (the downstream trace of a hovered gradient, namespaces `d` and `n`) and `BACK_STAGES` (the backward pass's stages, in order).
- `ui/trained.js` has a second key, `dl-explorer.vit-weights.v1`, with `saveTrainedViT` and `loadTrainedViT`; the CNN key is unchanged.
- three.js r128 UMD from cdnjs; OrbitControls is not in that build, so `ui/blocks3d.js` has its own small orbit implementation. External scripts only from cdnjs or jsDelivr, pinned.

## Open questions and known gaps
- Intent does not say who the tool is for; the first court can capture it.
- "Different activation plots for each new pass" (Alexy, 2026-10-13) was read as each digit's forward pass, which the live band shows. If it meant passes over the data set (epochs), a per-pass view, for example the same digits' activations after each pass, is not built.
- In the training 3D view side by side, at the whole preset, the labels of the narrow head blocks (pool 2, global avg, softmax and their gradients) overlap; they separate when zoomed or at the forward and backward presets.
- Do the ViT's two heads specialise? Partly answered: their maps differ substantially (mean row-wise total-variation distance 0.70 over 200 digits). What each head attends to is still open.
- The ViT page's green, scaled to the largest other weight, can exaggerate a row that mostly attends to itself (self-weight: median 0.008, 90th percentile 0.10, max 0.86); the readout's real numbers cover it.
- The ViT's data hunger, a limitation the Intent asks the tool to show, now appears in the measurements: with 100 digits the CNN leads in every seed, by 22 to 34 points (27 on average); from 1,000 digits the two are level on average (see Results, 2026-10-28).
- A position table with grid structure would need far more data (60,000 MNIST digits, or augmentation); untested.
- The toy network tops out around 80 to 85% on held-out digits. Closer to LeNet numbers would need a bigger network (more kernels or a hidden FC layer), which breaks the shared-network premise of the three pages; for Alexy to decide.
