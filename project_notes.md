## As built
_Kept up to date by Claude._
### Overview
Interactive web pages, with no build step, that show what the boxes in a deep-learning architecture diagram actually compute. Three pages exist, all for the same toy CNN: a 2D page (convolution one output cell at a time, ReLU, pooling, channels, receptive field, through to a prediction), a 3D page (the same network drawn as H×W×C blocks with three.js, with kernel sweeps and receptive-field cones), and a training page (real MNIST digits shrunk to 16×16 stream in; one SGD step is shown in full, forward, loss, backward, update, then the arc of many with curves, kernels over time and accuracy on held-out digits; weights trained there load into the other two pages). The repo's CLAUDE.md says: "Purpose: interactive, visual explanations of how DL architectures compute (CNN first; ViT, ConvNeXt, CoAtNet next). The audience is someone who uses these models daily and wants the concrete steps behind diagrams like 'Conv 3×3 → ReLU → MaxPool → … → FC'." Alexy, 2026-10-12: the project is to "visualise different models, starting with DL", ported locally "to add to it without being limited by artifacts size, versioning and such."

### Method
- Plain HTML plus ES modules, served statically. GitHub Pages deploys the repo root from `main` (`.github/workflows/pages.yml`). Local run: `python -m http.server 8000` from the repo root (modules need http, not file://); maths test: `node core/cnn.test.mjs`.
- Toy network: 16×16×1 input → conv1 (4 hand-picked 3×3 kernels: Sobel-x, Sobel-y, Laplacian, diagonal; stride, padding and dilation selectable) + ReLU → 2×2 pool (max or average, a toggle on both pages) → conv2 (8 random 3×3×4 kernels) + ReLU → 2×2 pool → global average (8 values) → FC 8×10 (random) → softmax over 10 classes. The 2D page can also switch the activation off. Nothing is trained; the pages say so wherever a prediction appears.
- `core/cnn.js` holds the forward pass, pooling, softmax, receptive-field propagation and the kernel and input presets, as pure functions with a test. Both pages are ES modules (`<script type="module">`) that import it; each keeps only display code plus two thin wrappers: the 2D page builds the zero-padded input it draws in stage 2, and both pages resolve the head probes (a global-average entry, a class, a score, an input pixel) before calling the core `footprint`. `forward` takes `activation: 'relu' | 'none'` (the 2D ReLU toggle) and `poolMode: 'max' | 'avg'`; `footprint` takes one cell `{stage, r, c, ch}` or a region `{stage, rect, ch | chs}`.
- Interaction grammar shared by every page: yellow = forward kernel window, green = receptive field traced backward; hovering any cell highlights its receptive field in every upstream tensor; technical terms get a dotted inline definition plus a Terms section on both pages. The 3D readout for a pooled cube writes out the 2×2 block it summarises, as the 2D page does. At the head, both pages show only the direct link: a global-average entry lights its pool-2 map, an FC weight lights its average and its class, a class lights the 8 averages and its column of W; the cone back to the input is not drawn there.
- `ui/terms.js` and `ui/terms.css` hold the terms mechanism (the `TERMS` array, the dotted definitions with their tooltip, the Terms section); both pages import `installTerms` with their own text selectors. Terms are linked at their first mention per paragraph, in order of appearance; dynamic text (readouts, the sweep hint) is left unlinked.
- 3D depth layout: the default "whole network" camera looks from high up and nearly head-on from the input end, so the stages recede as a staircase and the input hides nothing; chosen from headless-Edge screenshots of nine candidate presets at two window widths.
- `core/train.js` holds the training maths as pure functions: cross-entropy loss; the backward pass (scores p − y → FC → global average, a 16th to each cell → pool routing, max to the first maximum or average spread → ReLU gate → conv kernel and input gradients at stride 1, pad 1); He-uniform initialisation (±√(6/fan_in), seeded, or the hand-picked bank for layer 1); one SGD step; batch averaging; prediction; accuracy; a seeded shuffled order. `core/data.js` reads `data/mnist16.bin`: 3,000 training and 1,000 test MNIST digits, 300 and 100 per class, area-resampled from 28×28 to 16×16 by `tools/make_mnist16.py` (standard-library Python, seed 1; format and CC BY-SA 3.0 attribution in `data/README.md`).
- Training page `cnn-train/`. Band 1, One step: a phase strip digit → forward → backward → update; Step runs one phase, Next digit finishes the digit and brings the next; the forward row; the backward row of ∂L/∂activation maps in the same positions, starting from p − y at the scores; weight · gradient · updated-weight triplets per layer (layer 2 drawn as its four slices side by side); hovering any weight writes its gradient and update out and outlines the two maps it is the product of. Band 2, Many steps: play at 10, 50 or 200 digits a second (default 200), learning rate 0.001 to 0.5 (default 0.1), batch 1, 8 or 32, Reset with the next seed, start layer 1 from the edge detectors; loss per digit and its running average; training accuracy over the last 200 digits and held-out accuracy on the 1,000 test digits every 200; layer-1 kernels at 0, 100, 300, 1,000, 3,000 and 10,000 digits; the last 20 digits with their guesses. The maths runs at full speed in a frame loop; drawing is throttled to ten refreshes a second.
- Hand-off: "Use these weights" stores them in local storage (`ui/trained.js`, key `dl-explorer.weights.v1`, with digits seen, passes, held-out accuracy, learning rate, date); the 2D and 3D pages load them at start, show a banner with a "back to the hand-picked kernels" link, and change their "weights are random" wording. "Download JSON" saves the same object.
- `ui/grid.js` holds the canvas grid drawing and hit-testing (`drawGrid`, `cellAt`, colours, `fmt`) shared by the 2D and training pages.
- three.js r128 UMD from cdnjs; OrbitControls is not in that build, so the 3D page has its own small orbit implementation. External scripts only from cdnjs or jsDelivr, pinned.

### Results
- 2026-10-12: `node core/cnn.test.mjs` passes (laptop, Node 24.19.0, repo at commit 6a95715): output-size formula, identity kernel, max pool, softmax sums to 1, shapes 16 → 8 → 4, receptive field of pool2 cell (1,1) = input rows 1–10, cols 1–10.
- 2026-10-12: wiring check (laptop, Node 24.19.0 and headless Edge, commit a09b700). `node core/cnn.test.mjs` passes, now also covering `activation: 'none'`, average pooling and region probes. The pages' old inline maths (from commit 6a95715) and `core/cnn.js` agree bit for bit on every tensor of the forward pass over all reachable settings (2D: stride 1–3, padding 0–2, dilation 1–2, ReLU on/off, max/avg pooling; 3D: stride 1–2, padding 0–1, dilation 1–2), all seven input presets, fixed random layer-2 and FC weights, and on the receptive field of every cell of every stage and channel plus the head probes: 560 forward configurations, 21,384 probes, 27,572 comparisons, 0 differences (one-off script in the session scratchpad, not in the repo). Headless Edge rendered the old and new pages with the same seeded `Math.random`: identical DOMs once script blocks are stripped, no page console errors.
- 2026-10-12: step-2 check (laptop, headless Edge with SwiftShader WebGL, Node 24.19.0, commit after a09b700). In depth layout at 1400 px and 1000 px window widths the 3D page shows all seven stages, input to softmax, with nothing hidden or under the readout. With average pooling selected and a pool-1 cube probed, the readout writes out the 2×2 block (`avg( ... ) = ...`). Dotted terms: 30 on the 2D page (19 before the ordering fix in `linkTerms`), 4 on the 3D page (channels, receptive field, kernel, FC: its static text mentions few terms); glossary 16 entries on both. The 2D padding dropdown renders with 1 selected. No page console errors. `node core/cnn.test.mjs` passes.
- 2026-10-12: training maths (laptop, Node 24.19.0, `node core/train.test.mjs`). Gradients against central finite differences on an 8×8 random instance, 414 parameters: max normalised error 5.5e-5 with max pooling and 1.5e-5 with average pooling, medians 5.8e-7 and 2.5e-7. 50 SGD steps on one digit at lr 0.1: loss 2.19 → 0.004. Three passes over the 3,000 training digits (lr 0.1, batch 1, He-uniform init, seed 1): held-out accuracy 10.0 → 51.2 → 56.8 → 82.4% in 4 s. Ten passes: about 83%, noisy pass to pass (68 to 83%); from the edge-detector start 86%. With ±1/√fan_in init one pass reached 29% and ten passes 80%. Whatever the setting, the first several hundred digits are a plateau at chance (loss near 2.3); the page says so.
- 2026-10-12: training page checks (laptop, headless Edge). The page loads with no console errors; scripted phases give the expected phase strip, 27 forward and 26 backward canvases, triplets with three grids per layer after backward and one after update, and the probe readout `W[row 3, class 3] … ∂L/∂W = gap[3] × (p[3] − y[3]) …`; 300 digits of scripted play fill the curves, four kernel snapshots and 20 thumbnails; screenshots at 1400 and 1000 px and in dark theme read correctly. The 2D page's move to `ui/grid.js` left its rendered DOM identical (seeded). The explorer pages without stored weights differ from before only by the banner stylesheet and a span; with stored weights the banner and the wording appear; the training page's "use these weights" writes the key. All four pages served from one server load without console errors.
- The toy's held-out accuracy is the only accuracy figure; the explorer pages' default weights are still hand-picked or random.

### Decisions
- 2026-10-12: The repo lives in a local `repos` folder outside OneDrive, not in the OneDrive project folder. Why: on this laptop, shell tools (git, node, python) cannot write under the synced Documents folder; only Claude's Write/Edit tools can. The OneDrive folder keeps the original zip and a pointer README.
- 2026-10-12: First commit imports the artifact export unchanged, so the pages on `main` are exactly the published artifacts. Why: a clean baseline before the shared-module refactor.
- 2026-10-12: VS Code and Claude Code are opened on the repo, not on the OneDrive folder, from here on. Why: Alexy, after the port ("I'll continue on the proper folder afterwards"); notes and Claude memory live with the repo.
- 2026-10-12: The pages import `core/cnn.js` as ES modules instead of carrying inline copies of the maths. The 2D ReLU toggle and the head probes went into the core (an `activation` option, region probes for `footprint`) rather than staying as page-side copies of the propagation loop. Why: one copy of the maths, and the page wrappers stay a few lines each.
- 2026-10-12: The terms mechanism moved out of the 2D page into a new `ui/` folder (shared DOM code; `core/` stays DOM-free) instead of being copied into the 3D page. Why: the CLAUDE.md rule says reuse it, and step 1 had just removed the other duplicate.
- 2026-10-12: `linkTerms` links each term at its first occurrence, in order of appearance, instead of in `TERMS` order within the text left after the previous match. Why: the old order skipped terms ("receptive field" in the 3D lede came before "kernel" and was never linked); the 2D page gained 11 dotted terms from the change.
- 2026-10-12: The depth-layout default camera looks from the input end, high and nearly head-on, not from the output end looking back (the handoff offered both). Why: from the output end, perspective shrinks the far input and reverses the funnel the lede describes; from high up the funnel reads as a staircase and nothing occludes.
- 2026-10-12: The 2D padding dropdown marks 1 as selected. Why: it showed 0 while the model computed with 1.
- 2026-10-12: Public GitHub repo `Smooth-Cactus0/Visualising-AI`, deployed with GitHub Pages from `main`. The name is Alexy's "Visualising AI" with GitHub's own space-to-hyphen conversion. Why: Pages is free for public repos; a private repo would need a paid plan.
- 2026-10-12: The 2D page's head probes show only their direct link, as the 3D page already did: a global-average entry → its pool-2 map; an FC weight (now hoverable) → its average and its class; a class → the 8 averages and its column of W. Why: Alexy, 2026-10-12: hovering a class lit every upstream map, and hovering an FC weight lit nothing; the artifact-session decision already said the cone is omitted at the head.
- 2026-10-12: Local paths, the Windows username and the IT-policy detail were removed from these notes once the repo was public; the local path lives in Claude's private memory. Commits from this repo now use GitHub's no-reply address. Why: Alexy, 2026-10-12, after the repo went public.
- 2026-10-12: Training page as two stacked bands (One step, Many steps) on one page, chosen over a mode switch and over two columns. Why: Alexy, 2026-10-12: "the step is important but seeing weights being actualised over passes is necessary too"; both must be visible together.
- 2026-10-12: The training page keeps the 16×16 network of the other pages and trains live in the browser with plain SGD, rather than 28×28 or replaying an offline run. Why: the trained weights plug into the 2D and 3D pages, and learning rate and batch stay interactive. The cost, measured: about 80 to 85% held-out, not LeNet's 99%.
- 2026-10-12: Weights drawn as weight · gradient · updated-weight triplets, the arithmetic written out on hover; an arrow overlay is kept in reserve. Why: Alexy chose the triplets in the brainstorm ("might do B depending on final product").
- 2026-10-12: He-uniform initialisation and a default learning rate of 0.1, replacing ±1/√fan_in and 0.05. Why: measured; the first pair learned too slowly (29% after one pass). The brainstorm's guess of 85 to 92% was corrected to the measured 80 to 85% on the page and in the spec.
- 2026-10-12: The early plateau (loss near 2.3 for several hundred digits) is explained on the page, not hidden, and the default play speed is 200 digits a second so it lasts seconds. Why: it is a real property of training from random kernels; the step band is throttled to ten refreshes a second anyway.
- Carried over from the artifact sessions (HANDOFF.md, "Decisions already taken"): the 3D second view is stages along depth with connections, not volumetric 3D convolution; head wiring links only direct neighbours (an average to its own pool-2 map, a class to the 8 averages); no shape/parameter table, the proportional ledger replaced it; padding is not drawn as cubes in 3D, the layer-1 window overhangs the input instead; layer-1 kernels are Sobel-x, Sobel-y, Laplacian and diagonal, layer 2 and the FC are random with reroll buttons.
