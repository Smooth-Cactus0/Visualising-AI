ViT explorer

A ViT diagram says "patch embedding → + position → encoder (Norm → multi-head attention → + → Norm → MLP → +) → classifier". This page runs one small enough that every number fits on screen: a 16×16 digit cut into 16 patches, 8 numbers per token, one encoder block with two attention heads, 1,242 weights. The line below is the whole forward pass, token i always on row i; the sections zoom into one part at a time.

the window being computed: one patch, or one score what a hovered value is computed from; after attention, shaded by attention weight learned weights, where they act

1 · Patches become tokens

4×4 kernels, stride 4 → 16 tokens × 8

The patch embedding is a convolution whose kernel is as big as its stride: 4×4 kernels jumping 4 pixels at a time, so the windows tile the digit without overlapping. Each of the 8 kernels gives one number per patch, so each patch becomes a token of 8 numbers, one row. It is the CNN page's kernel, jumping instead of sliding. Click a kernel to write its column out.

2 · Position

z₀ = tokens + position table

Attention by itself does not know where a patch came from: shuffle the patches and, without position, every token keeps its content and the average of the tokens comes out the same. So a learned position table, one row of 8 numbers per slot, is added to the tokens. Try "Shuffle patches" at the top, with position on and then off.

3 · One attention head, written out

A = softmax(Q·Kᵀ / 2), output = A·V

Each token makes a query, a key and a value from its LayerNorm output: three learned 8×8 matrices, of which each head uses 4 columns. Token i's score for token j is query i · key j / 2; a softmax along the row turns the scores into attention weights that sum to 1; token i's output is the weighted sum of the values. Keys and values stand as columns above the map, one per token, so each row of the map weights the columns directly above it.

Before this step a token had seen only its own patch; after it, every patch. The attention map is a receptive field that is global in one step, and computed from the image rather than fixed, unlike a kernel's window. The price: 16 tokens make 256 scores per head, and the count grows with the square of the number of patches, which is why real ViTs use large patches.

4 · Mix the heads, residual, MLP

z₁ = z₀ + heads·Wo, z₂ = z₁ + MLP(LayerNorm(z₁))

The two heads' outputs are joined back into 8 numbers and mixed by Wo, and the block's input z₀ is added back, a residual connection, giving z₁. Then LayerNorm and an MLP, 8 → 32 → 8 with GELU, and z₁ is added back again. Every step here works on one token at a time, like a 1×1 convolution; attention was the only step where tokens met. A real ViT repeats this block 12 times or more.

5 · Average the tokens, then predict

mean of 16 tokens → LayerNorm → W head → softmax

The 16 tokens are averaged into 8 numbers, as the CNN's global average does with its maps; LayerNorm and W head turn them into 10 scores, and softmax into probabilities. The original ViT reads an extra class token instead; with a single block only that token's row would reach the answer, so this toy uses the average of the tokens, as many current ViTs do. The ViT training page trains it live and races it against the CNN.
